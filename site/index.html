Find out where your disk went.

Then get it back — with a figure you can hold the tool to. nix is a storage manager for Linux that measures what it is about to delete, and tells you when it cannot promise the space will come back.

Install nix Read the source

What it does

Shows you the disk

A scan that attributes every byte to something, down a tree you can walk. Sizes are what the filesystem has committed, not what the files claim to contain.

Reclaims it, on your say-so

Caches, logs, superseded packages, old kernels, build output, container images. You see every item and what losing it costs before anything is touched.

Watches the machine

CPU, memory, disks, network, temperatures and battery, sampled only while you are looking. Close the window and it stops.

Manages what is installed

Packages, services and timers, startup entries, software sources and the hosts file — each read from the system rather than guessed at.

What it will not do

  • Touch anything you made. Documents, pictures, projects, configuration. It reclaims things that regenerate themselves, and things you have chosen.
  • Remove the kernel you are running, or the newest one installed. Refused by the interface, and refused again by the privileged process that would have to carry it out.
  • Count the trash as freed. The trash is on the same disk, so moving something there frees nothing until you empty it. That is reported as its own figure.
  • Claim a number it has not measured. Where space is shared with a filesystem snapshot it says up to, and afterwards it checks its own arithmetic against the filesystem and tells you if the two disagree.
  • Ask for your password more than it needs to. Once per batch, through polkit, and only for operations that genuinely require it.

Numbers it is held to

Each of these is asserted by a test that fails the build when it regresses. Measured on the machine nix was written on — an eight-core desktop running Ubuntu 22.04.

Measured Result Ceiling
Subprocesses spawned while monitoring 0 none permitted
Processor used with the monitor open 0.75% of one core 1%
Memory held after a full scan 45.7 MiB 150 MB
Time to read a file while scanning 4.65 µs 10 µs
Time to list 757 system services 11.7 ms 500 ms

The first row is the one worth explaining: nix reads the kernel's own interfaces directly, so nothing is launched on a timer to sample your machine. Listing those services takes one call rather than 1,515 of them.

Install

Version 0.2.0, for x86-64 Linux. Built on Ubuntu 22.04, so it runs on that and anything newer.

Debian, Ubuntu and derivatives

sudo apt install ./nix_0.2.0_amd64.deb

Fedora and RPM distributions

sudo dnf install ./nix-0.2.0-1.x86_64.rpm

Arch, from source

makepkg -si

Download from the releases page

The .deb and .rpm install a small privileged helper and its polkit policy, which is what lets nix reclaim system space. An AppImage is also published, but polkit identifies a program by its absolute path and an AppImage does not have a fixed one — so privileged features report themselves unavailable there rather than failing when you try to use them.

Where it is up to

nix is not 1.0 yet. Everything above is built and tested, and some of it has been tested only against the machine it was written on: the package backends for Fedora, openSUSE and Arch are written to documented output and have never met a real installation of those systems, and the operations that delete system files have never run as root outside a test. Those are listed, one by one, with what is missing.

Every defect found while building it is written down too — what it was, how it surfaced, and what now stops it recurring. There are seventy-one of them.
